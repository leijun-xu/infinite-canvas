# Infinite Canvas 项目本地启动

## 最短结论

如果你只是想先看到项目页面，只需要启动 `web/`：

```bash
cd /Users/bytedance/Desktop/infinite-canvas-main/web
bun install
bun run dev
```

然后在浏览器打开：

```text
http://localhost:3000
```

`canvas-agent`、`canvas-proxy`、`docs` 都不是主页面启动的必需项，可以等主应用正常运行后再按需启动。

## 一、启动前准备

### 1. 确认当前项目目录

项目当前位于：

```text
/Users/bytedance/Desktop/infinite-canvas-main
```

在终端执行：

```bash
cd /Users/bytedance/Desktop/infinite-canvas-main
pwd
```

正常应输出：

```text
/Users/bytedance/Desktop/infinite-canvas-main
```

### 2. 安装 Bun

主应用和文档站推荐使用 Bun。

先检查：

```bash
bun --version
```

如果提示找不到命令，可以在 macOS 上执行：

```bash
curl -fsSL https://bun.sh/install | bash
```

安装完成后重新打开一个终端，再次检查：

```bash
bun --version
```

### 3. 安装 Node.js

`canvas-agent` 和 `canvas-proxy` 要求 Node.js 18 或更高版本。

检查：

```bash
node --version
npm --version
```

如果你只启动 `web/`，暂时不运行 Agent 和 Proxy，可以先不处理它们。

### 4. 可选：安装 Docker

只有选择 Docker 启动方式时才需要 Docker Desktop。

检查：

```bash
docker --version
docker compose version
```

## 二、推荐方式：启动主应用

### 第一步：进入前端目录

```bash
cd /Users/bytedance/Desktop/infinite-canvas-main/web
```

### 第二步：安装依赖

```bash
bun install
```

第一次安装需要下载依赖，时间取决于网络环境。安装完成后会生成或使用 `node_modules/`。

### 第三步：启动开发服务器

```bash
bun run dev
```

正常情况下，终端会看到类似：

```text
Local: http://localhost:3000/
```

这个终端需要保持运行。不要关闭它，否则网页服务会停止。

### 第四步：打开页面

浏览器访问：

```text
http://localhost:3000
```

如果能看到 Infinite Canvas 首页，说明主应用已经启动成功。

## 三、首次使用配置

页面能打开不代表 AI 生成功能已经可用。项目不会自带可用的 API Key。

### 1. 打开配置

进入页面后，点击右上角的配置入口。

### 2. 配置模型渠道

需要根据你的 AI 服务提供方填写：

- 渠道名称。
- Base URL。
- API Key。
- 接口格式：OpenAI 或 Gemini。
- 模型名称。
- 模型能力：图片、视频、文本或音频。

项目会根据能力分别选择：

- 图片模型。
- 视频模型。
- 文本模型。
- 音频模型。

### 3. 保存位置

当前配置主要保存在浏览器本地。

需要注意：

- API Key 存在当前浏览器中。
- 浏览器会直接请求你配置的模型服务。
- 项目默认没有业务后端代为保管 API Key。
- 更换浏览器或清理站点数据后，配置可能丢失。

### 4. 测试最基本功能

建议按下面顺序测试：

1. 打开首页。
2. 进入 `/canvas`。
3. 新建一个画布。
4. 创建文本或图片节点。
5. 确认画布拖动、缩放和节点操作正常。
6. 配置模型后再测试 AI 生成。

这样可以区分“前端没有启动成功”和“模型接口配置错误”。

## 四、什么时候需要启动 `canvas-proxy`

### 使用场景

如果页面请求 AI 接口时出现浏览器跨域错误，例如控制台中包含：

```text
CORS
blocked by access-control-allow-origin
```

可以启动本地代理。

它只负责转发请求，不提供模型能力。

### 启动当前仓库中的代理

新开一个终端，不要关闭正在运行 `web` 的终端。

执行：

```bash
cd /Users/bytedance/Desktop/infinite-canvas-main/canvas-proxy
npm install
npm run start
```

默认地址：

```text
http://127.0.0.1:23210
```

终端正常会显示：

```text
@basketikun/canvas-proxy ... listening on http://127.0.0.1:23210
```

### 在网页中启用

进入：

```text
配置 → 本地代理
```

填写：

```text
http://127.0.0.1:23210
```

然后开启代理。

### 检查代理是否在线

浏览器直接打开：

```text
http://127.0.0.1:23210/
```

如果返回包含包名和版本的 JSON，说明代理服务已启动。

### 安全提醒

代理默认只监听本机，这是正确的安全设置。

不要为了让其他机器访问而随意改成：

```text
0.0.0.0
```

它没有登录认证，并且可以转发任意 HTTP/HTTPS 地址，不适合暴露到公网。

## 五、什么时候需要启动 `canvas-agent`

### 使用场景

只有需要下面能力时才启动：

- 在网页右侧使用本地 Agent 对话。
- 让 Codex 读取当前画布。
- 让 Codex 创建、修改或连接画布节点。
- 使用 MCP 操作 Infinite Canvas。

普通画布编辑和模型生成功能不依赖它。

### 方式一：运行当前仓库源码

新开一个终端：

```bash
cd /Users/bytedance/Desktop/infinite-canvas-main/canvas-agent
npm install
npm run dev
```

正常会显示：

```text
Local URL: http://127.0.0.1:17371
Connect token: xxxxxx
```

保持这个终端运行。

### 方式二：运行已发布的 npm 包

如果只是使用 Agent，不调试当前源码，可以执行：

```bash
npx -y @basketikun/canvas-agent@latest
```

如果你正在修改本仓库的 `canvas-agent` 源码，应使用方式一，否则运行的是 npm 上已经发布的版本。

### 连接网页

1. 保持 `web` 和 `canvas-agent` 两个终端都在运行。
2. 打开 `http://localhost:3000`。
3. 进入一个具体画布。
4. 打开右上角 Agent 面板。
5. 填入启动日志中的 Local URL。
6. 填入 Connect token。
7. 点击连接。

### Agent 本地文件

Canvas Agent 会使用：

```text
~/.infinite-canvas/
```

其中可能包含：

- `canvas-agent.json`：URL、token、允许的 Origin、工作空间配置。
- `logs/`：Debug 日志。
- `codex-workspaces/`：Agent 使用的本地工作空间。

不要把这里的 token 提交到 Git。

### 开启 Debug 日志

运行仓库源码：

```bash
cd /Users/bytedance/Desktop/infinite-canvas-main/canvas-agent
npm run debug
```

运行已发布版本：

```bash
npx -y @basketikun/canvas-agent@latest --debug
```

仅在排查连接、线程、Codex app-server 或工具调用问题时使用。

## 六、可选：注册 MCP

只启动 Canvas Agent HTTP 服务，不会自动把 MCP 工具安装到 Codex。

### 使用已发布版本注册

```bash
codex mcp add infinite-canvas -- npx -y @basketikun/canvas-agent@latest mcp
```

### 使用当前仓库源码注册

源码方式需要先构建：

```bash

npm install
npm run build
```

然后注册：

```bash

```

检查注册：

```bash
codex mcp list
```
node /Users/bytedance/Desktop/infinite-canvas-main/canvas-agent/dist/index.js   

### 检查完整链路

MCP 工具可用需要同时满足：

1. Canvas Agent HTTP 服务正在运行。
2. MCP 已注册到 Codex。
3. 浏览器画布已经打开。
4. 网页已使用正确 URL 和 token 连接 Agent。

缺少任意一项，都可能出现“当前没有已连接画布”。

### 移除 MCP

不再使用时：

```bash
codex mcp remove infinite-canvas
```

在项目根目录执行：


打开：



### 方式二：手动构建镜像

```bash
cd /Users/bytedance/Desktop/infinite-canvas-main
docker build -t infinite-canvas .
docker run --rm -p 3000:3000 infinite-canvas
```

### 注意区分两个 Compose 文件

根目录：

```text
docker-compose.yml
```

使用已经发布的远程镜像：

```text
ghcr.io/basketikun/infinite-canvas:latest
```

根目录：

```text
docker-compose.local.yml
```

会根据当前本地源码构建镜像。

如果你要验证自己刚修改的代码，应使用 `docker-compose.local.yml`。

### Docker 模式的边界

Docker 镜像只托管构建后的静态前端：

- 不包含 Canvas Agent。
- 不包含 Canvas Proxy。
- 不代替 AI 模型服务。
- API Key 仍在浏览器本地。
- AI 请求仍由浏览器直连用户配置的接口。

## 十二、常见问题排查

### 1. `bun: command not found`

说明 Bun 未安装或终端还没有加载新的环境变量。

处理：

```bash
curl -fsSL https://bun.sh/install | bash
```

然后关闭并重新打开终端。

### 2. `node: command not found`

只有启动 Agent 或 Proxy 时需要 Node.js。

安装 Node.js 18 或更高版本后，重新执行：

```bash
node --version
npm --version
```

### 3. 端口 `3000` 被占用

先检查：

```bash
lsof -nP -iTCP:3000 -sTCP:LISTEN
```

如果是之前启动的项目终端，回到那个终端按 `Control + C`。

不要直接杀掉不认识的进程，先确认进程用途。

### 4. 页面能开，但生成失败

依次检查：

1. Base URL 是否正确。
2. API Key 是否有效。
3. 模型名称是否正确。
4. 模型能力是否配置正确。
5. 浏览器开发者工具 Network 中的状态码。
6. 是否是 CORS；如果是，再启动 Canvas Proxy。

常见状态：

- `401`：API Key 无效。
- `403`：权限不足或服务拒绝。
- `404`：Base URL、路径或模型名错误。
- `429`：额度、频率或并发限制。
- `5xx`：上游模型服务异常。

### 5. 刷新后画布还在，但换浏览器没有

这是当前设计。

画布、素材和生成记录主要保存在当前浏览器的 IndexedDB，不是默认云端账号数据。

跨浏览器或跨设备需要：

- 手动导入导出。
- 或配置 WebDAV 同步。

### 6. Agent 面板连接失败

检查：

1. `canvas-agent` 终端是否仍在运行。
2. URL 是否为 `http://127.0.0.1:17371`。
3. token 是否完整复制。
4. 浏览器是否访问了正确的本地前端地址。
5. 是否更换过 Origin。
6. Debug 日志中是否有 `origin not allowed` 或 `invalid token`。

### 7. Codex 有 MCP，但提示没有画布

MCP 注册成功不等于网页已经连接。

确认：

- Canvas Agent HTTP 服务正在运行。
- 网页已打开具体画布。
- 网页 Agent 面板显示已连接。
- 当前标签页是活跃画布。

### 8. 代理在线，但请求仍失败

代理只解决 CORS，不能解决：

- API Key 错误。
- 模型不存在。
- 余额不足。
- 上游接口格式不兼容。
- 服务商自身异常。

查看 Proxy 终端打印的上游状态码。

### 9. 文档站启动到了其他端口

如果没有显式指定 `3001`，Next.js 发现 `3000` 被占用时可能选择其他端口。

推荐固定执行：

```bash
bun run dev -- -p 3001
```

### 10. 插件改了但页面没变化

检查：

1. 插件的 `npm run dev` 是否仍在运行。
2. `web/public/plugins/<name>.js` 是否生成。
3. 插件是否在管理器中启用。
4. 是否刷新了画布页面。
5. 是否需要配置 `VITE_DEV_PLUGINS`。

## 十三、推荐的首次启动顺序

第一次运行建议严格按这个顺序：

1. 安装 Bun。
2. 只启动 `web/`。
3. 打开 `http://localhost:3000`。
4. 新建画布，确认基础交互正常。
5. 配置自己的模型渠道。
6. 测试一次文本或图片请求。
7. 只有出现 CORS 时再启动 `canvas-proxy`。
8. 需要 Codex 操作画布时再启动 `canvas-agent`。
9. 修改文档时再启动 `docs`。
10. 开发插件时再启动对应插件的 watch。
