# Infinite Canvas 项目分析

## 项目定位

`infinite-canvas` 是一个面向图片、视频、音频、文本创作的无限画布工作台。用户在浏览器中配置 OpenAI 兼容接口后，前端直接请求模型接口，把生成结果保存到浏览器本地，并通过画布节点和连线组织创作流程。

项目整体是“浏览器本地优先”的架构：

- 核心应用在 `web/`。
- 画布、素材、生成记录、AI API Key 默认保存在浏览器本地。
- `canvas-agent/` 和 `canvas-proxy/` 是可选的本地辅助服务。
- `plugins/` 提供画布节点插件和 Codex / ZCode app 插件。
- `docs/` 是独立文档站。

## 顶层目录说明

### `web/`

核心前端应用，技术栈是 Vite、React 19、React Router、Ant Design、Tailwind、Zustand、localforage。

主要职责：

- 提供无限画布主界面。
- 提供图片、视频、音频、文本模型调用能力。
- 管理画布项目、节点、连线、素材、提示词库和本地配置。
- 通过浏览器直连 OpenAI / Gemini 兼容接口。
- 连接本地 Canvas Agent，实现网页画布和 Codex / Claude Code 的协作。

### `canvas-agent/`

本地 Agent 服务，是一个独立 Node 包。

主要职责：

- 启动本地 HTTP 服务，默认监听 `127.0.0.1`。
- 连接网页画布和 Codex / Claude Code。
- 提供 MCP 服务，让 Codex / Claude 可以通过工具操作画布。
- 管理 Agent 对话线程、事件流、工具调用、审批、技能草稿等。

入口文件是 `canvas-agent/src/index.ts`：

- 默认启动 HTTP 服务。
- 传入 `mcp` 参数时启动 MCP 服务。

### `canvas-proxy/`

本地 CORS 转发代理。

浏览器直连第三方 AI 接口时可能遇到跨域问题，启动该代理后，网页可以先请求本机代理，再由代理转发到目标 API。

它只做转发：

- 不改写请求体。
- 不校验 API Key。
- 不落盘日志。
- 默认只监听 `127.0.0.1`。

### `plugins/`

插件体系目录，包含两类插件。

`plugins/canvas/` 是画布节点插件体系：

- `sdk/`：插件 SDK，提供类型、 JSX runtime、构建工具。
- `template/`：新插件起步模板。
- `markdown/`：Markdown 节点插件。
- `svg/`：SVG 节点插件。
- `html/`：HTML 节点插件。
- `panorama/`：3D 全景节点插件。
- `sticky-note/`：便利贴节点插件。
- `registry/`：官方插件注册表构建与发布。

`plugins/infinite-canvas/` 是 Codex / ZCode app 插件：

- 用于让 Codex / ZCode 打开并连接 Infinite Canvas。
- 会注册同一个 `infinite-canvas` MCP。
- 可通过插件命令启动本地 Agent 并打开画布。

### `docs/`

文档站，是一个独立 Next.js + Fumadocs 项目。

主要职责：

- 承载快速开始、功能介绍、Docker 部署、Render 部署、画布手册、快捷键、开发文档、TODO、待测试事项等内容。
- 提供文档搜索、国际化和 `llms.txt` / `llms-full.txt` 输出。

重点目录：

- `docs/content/docs/`：实际文档内容。
- `docs/src/app/`：Next App Router 页面和 API。
- `docs/src/lib/`：文档源、i18n、搜索等能力。
- `docs/public/`：文档站静态资源。

### `assets/`

README 中使用的赞助商和展示资源，例如图片、logo、SVG 等。

### `.agents/`

项目内 Agent skill 配置目录。

当前包含：

- `frontend-design`：前端设计相关 skill。
- `vercel-react-best-practices`：React / Next.js 性能实践相关 skill。

### 根目录配置文件

- `README.md`：项目介绍、核心功能、快速开始、赞助信息。
- `AGENTS.md`：本项目 AI / 自动化开发行为约束。
- `Dockerfile`：构建 Vite 前端产物，并用 nginx 托管静态资源。
- `nginx.conf`：Docker 运行时 nginx 配置。
- `docker-compose.yml`：生产镜像运行配置，默认暴露 `3000`。
- `docker-compose.local.yml`：本地 compose 配置。
- `render.yaml`：Render 部署配置。
- `vercel.json`：Vercel 部署配置。
- `VERSION`：项目版本号。
- `CHANGELOG.md`：版本变更记录。
- `SECURITY.md`：安全漏洞提交说明。
- `LICENSE`：MIT 开源协议。
- `skills-lock.json`：技能锁定信息。

## `web/src` 目录说明

### `main.tsx`

前端入口文件。

主要逻辑：

- 引入 Ant Design reset、Streamdown 样式和全局 CSS。
- 初始化统计分析。
- 初始化 i18n。
- 挂载 `AppProviders` 和 `RouterProvider`。

### `router.tsx`

页面路由配置。

当前路由包括：

- `/`：首页。
- `/image`：图片工作台。
- `/video`：视频工作台。
- `/assets`：我的素材。
- `/prompts`：提示词库。
- `/canvas`：画布项目列表。
- `/canvas/:id`：具体画布项目。
- `/config`：配置页。
- `*`：404 页面。

### `pages/`

路由页面目录。

- `home/`：首页。
- `image/`：独立图片生成页面。
- `video/`：独立视频生成页面。
- `assets/`：素材管理页面。
- `prompts/`：提示词库页面。
- `config/`：配置页面。
- `not-found/`：404 页面。
- `canvas/`：画布页面，是项目的业务中心。

### `pages/canvas/`

画布页面目录。

- `index.tsx`：画布项目列表页，负责创建、导入、导出、删除画布项目。
- `project.tsx`：画布详情页，是当前项目最大的业务中心。
- `hooks/use-agent-bridge.ts`：画布和本地 Agent 之间的桥接逻辑。
- `hooks/use-plugin-host.tsx`：画布插件宿主加载逻辑。

`project.tsx` 负责协调大量画布行为：

- 加载当前项目。
- 管理节点、连线、选区、视口、撤销重做。
- 处理节点拖拽、缩放、框选、右键菜单。
- 发起图片、视频、音频生成。
- 处理参考图、素材插入、节点编辑。
- 接入本地 Agent 和插件系统。

理解画布业务时，需要把 `project.tsx` 当作主调度器。

画布 UI 组件目录。

主要内容：

- `infinite-canvas.tsx`：画布容器，处理平移、缩放、背景网格。
- `canvas-node.tsx`：节点渲染。
- `canvas-connections.tsx`：连线渲染。
- `canvas-toolbar.tsx`：画布工具栏。
- `canvas-top-bar.tsx`：画布顶部栏。
- `canvas-side-panel.tsx`：画布侧边面板。
- `canvas-mini-map.tsx`：小地图。
- `canvas-context-menu.tsx`：右键菜单。
- `canvas-create-menus.tsx`：节点创建菜单。
- `canvas-selection-toolbar.tsx`：选区工具栏。
- `canvas-node-*-dialog.tsx`：节点裁剪、蒙版、拆分、放大、角度等编辑弹窗。
- `canvas-plugin-manager-modal.tsx`：插件管理器。
- `nodes/builtin-nodes.tsx`：内置节点注册。

### `components/agent/`

主要内容：

Zustand 状态目录。

核心 store：

- `canvas/use-canvas-ui-store.ts`：画布列表或 UI 级状态。
- `canvas/use-plugin-store.ts`：插件启用、安装、注册信息。

- `use-agent-store.ts`：本地 Agent 连接、消息、线程、审批、活动状态。
- `use-asset-store.ts`：我的素材。

## 核心运行链路

1. 浏览器打开 `web` 应用。
2. `main.tsx` 挂载 `AppProviders` 和 Router。
3. `AppProviders` 初始化主题、语言、Ant Design、React Query。
4. `router.tsx` 根据路径分发页面。
5. 进入 `/canvas/:id` 后，`pages/canvas/project.tsx` 加载当前画布项目。
6. 画布项目数据通过 `useCanvasStore` 保存到 localforage。
7. 图片、视频、音频生成请求走 `services/api/*`。
8. 请求配置来自 `use-config-store` 的模型渠道。
9. 生成结果通过 `image-storage.ts` 或 `file-storage.ts` 保存为 Blob。
10. 画布节点 metadata 记录 storageKey、尺寸、状态等信息。
11. 页面通过 storageKey 解析 Object URL 并渲染媒体。

## AI 请求链路

项目默认由浏览器前端直接请求用户配置的模型服务。

主要特点：

- API Key 保存在浏览器本地。
- Base URL 和模型渠道由用户在配置页维护。
- 支持 OpenAI 和 Gemini 格式。
- 支持图片、视频、文本、音频不同能力模型。
- 支持每个模型配置自定义脚本，以适配特殊中转站或自建服务。
- 可选启用 `canvas-proxy` 处理 CORS。

## 本地 Agent 链路

本地 Agent 是可选能力。

基本流程：

1. 用户启动 `canvas-agent`。
2. Agent 输出 Local URL 和 Connect token。
3. 用户在网页右上角 Agent 面板填入 URL 和 token。
4. 网页通过 HTTP 和 SSE 连接本地 Agent。
5. Agent 启动或复用 Codex / Claude 线程。
6. Codex / Claude 通过 MCP 工具读取画布状态、创建节点、应用操作。
7. 网页侧边栏展示事件流、消息、审批和工具调用结果。

可用 MCP 工具包括：

- `canvas_get_state`
- `canvas_get_selection`
- `canvas_export_snapshot`
- `canvas_apply_ops`
- `canvas_create_text_node`
- `canvas_create_image_prompt_flow`

## 插件链路

画布插件用于扩展自定义节点。

插件开发方式：

1. 复制 `plugins/canvas/template`。
2. 修改插件 `package.json`、`src/index.tsx` 中的插件 id 和节点类型。
3. 使用 `@infinite-canvas/plugin-sdk` 编写节点 UI 和逻辑。
4. 执行 `npm run build` 或 `npm run dev`。
5. 构建产物同步到 `web/public/plugins/<name>.js`。
6. 在画布插件管理器中启用。

插件可以访问：

- 当前节点数据。
- 当前画布主题。
- 上游 / 下游节点。
- 画布操作指令。
- 插件私有持久化存储。

注意：插件代码会在画布页面内直接执行，可以访问浏览器本地数据，包括 AI API Key，因此只应安装可信来源插件。

## 文档与部署

### 本地开发

核心前端：

```bash
cd web
bun install
bun run dev
```

本地 Agent：

```bash
cd canvas-agent
npm install
npm run build
node dist/index.js
```

本地代理：

```bash
cd canvas-proxy
npm install
npm run start
```

### Docker 运行

```bash
docker compose up -d
```

Docker 只构建并托管静态前端，AI 请求仍由浏览器前端直连用户自己的接口。

默认端口是 `3000`。

## 修改项目时的注意事项

- 先读现有代码，再动手修改。
- 项目尚未上线，不需要为旧数据做复杂兼容，除非明确要求。
- 画布相关代码优先遵循当前主题，不要硬编码黑白、stone、slate 等颜色。
- 浏览器业务数据默认使用 localforage，不要用 localStorage 保存大 JSON、图片、base64 或业务列表。
- 外部服务请求统一放在 `web/src/services/api/`。
- 全局或跨页面状态优先放在 `web/src/stores/`。
- 页面文案保持中文。
- 重大用户可感知改动需要更新 `CHANGELOG.md`。
- 每次任务完成前需要检查 `docs/content/docs/progress/todo.mdx` 和 `pending-test.mdx` 是否需要更新。
