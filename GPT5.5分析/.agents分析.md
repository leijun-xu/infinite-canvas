# `.agents` 目录分析

## 一句话理解

`.agents/` 是给 AI 编程 Agent 使用的项目级扩展配置，告诉 Agent 在这个仓库中可以使用哪些插件和专业开发规范。

它不是应用运行代码。普通用户打开 Infinite Canvas 时，浏览器不会加载这里的文件。

## 为什么目录名以点开头

在 macOS 和 Linux 中，以 `.` 开头的目录通常是隐藏配置目录。

`.agents/` 与下面这些目录性质类似：

- `.git/`：Git 内部数据。
- `.github/`：GitHub 工作流和模板。
- `.vscode/`：VS Code 工作区配置。

它服务开发工具，而不是产品页面。

## 当前结构

```text
.agents/
├── plugins/
│   └── marketplace.json
└── skills/
    ├── frontend-design/
    │   ├── SKILL.md
    │   └── LICENSE.txt
    └── vercel-react-best-practices/
        ├── SKILL.md
        ├── AGENTS.md
        ├── README.md
        ├── metadata.json
        └── rules/
```

## 先理解 Plugin 和 Skill

### Agent Plugin

Agent Plugin 是一个较完整的扩展包，可以包含：

- Skill。
- MCP Server。
- 图标和元数据。
- 安装配置。

### Skill

Skill 是一组专门任务的工作说明。

例如：

- 用户要求做高质量前端页面时，读取 `frontend-design`。
- 用户要求编写或优化 React 时，读取 `vercel-react-best-practices`。

Skill 更像“给 AI 的专业操作手册”，不是 JavaScript 函数，也不会被网页调用。

## `plugins/marketplace.json`

这是项目级插件市场配置。

当前注册了 `infinite-canvas` 插件，来源是：

```text
./plugins/infinite-canvas
```

主要字段：

- `name`：市场名称。
- `displayName`：界面显示名称。
- `plugins`：可发现的插件列表。
- `source.path`：插件所在相对路径。
- `policy.installation`：是否允许安装。
- `policy.authentication`：安装时是否需要认证流程。
- `category`：插件分类。

它的作用是让支持该格式的 Agent 工具在打开仓库后，能够发现本仓库内的 Infinite Canvas 插件。

## 与 `plugins/infinite-canvas/marketplace.json` 的区别

项目里还有：

```text
plugins/infinite-canvas/marketplace.json
```

两个文件名字相同，但位置和消费方可能不同：

- `.agents/plugins/marketplace.json`：项目级 Agent 插件发现入口。
- `plugins/infinite-canvas/marketplace.json`：插件目录自身的本地 marketplace 描述。

不要因为内容相似就随意删除或合并。修改时要确认目标 Agent 平台会读取哪个入口。

## `skills/frontend-design/`

### 用途

这个 Skill 指导 Agent 创建高质量、具有明确视觉方向的前端界面。

它强调：

- 先理解产品目的和目标用户。
- 选择明确的视觉风格。
- 避免千篇一律的 AI 页面。
- 重视字体、色彩、动效和空间布局。
- 输出真正可运行的前端代码。

### `SKILL.md`

Skill 的主入口。

文件顶部 YAML frontmatter 描述：

- Skill 名称。
- 适用场景。
- 许可证。

正文提供具体设计原则。

当用户要求创建或美化页面、组件、网站、Dashboard 等前端 UI 时，Agent 会使用这份说明。

### `LICENSE.txt`

该 Skill 自身的许可条款。

第三方 Skill 可能有独立许可证，不应因为主项目使用 MIT 就删除或覆盖它。

### 与项目 UI 规范的关系

Skill 提供通用设计方向，但项目根 `AGENTS.md` 提供本仓库的具体约束。

出现冲突时，应优先遵循项目规则和用户当前要求。例如项目规定画布工具栏应极简、低视觉重量，就不能仅因为通用设计 Skill 鼓励大胆效果而破坏现有画布风格。

## `skills/vercel-react-best-practices/`

### 用途

这是 Vercel 的 React / Next.js 性能优化规范集合。

适用于：

- 编写 React 组件。
- 编写 Next.js 页面。
- 优化数据请求。
- 减少 bundle。
- 减少重复渲染。
- 做前端性能审查。

### `SKILL.md`

Skill 入口和规则索引。

它把规则分成八类：

1. 消除异步瀑布。
2. Bundle 体积优化。
3. 服务端性能。
4. 客户端数据请求。
5. 重渲染优化。
6. 渲染性能。
7. JavaScript 性能。
8. 高级模式。

### `rules/`

每条规范一个 Markdown 文件。

例如：

- `async-parallel.md`：独立异步任务并行执行。
- `bundle-dynamic-imports.md`：重组件动态加载。
- `rerender-functional-setstate.md`：使用函数式状态更新。
- `js-set-map-lookups.md`：重复查找使用 Set / Map。

这种拆分让 Agent 可以只加载当前任务相关的规则，不必每次读取全部内容。

### `AGENTS.md`

把多条规则汇总成完整文档，适合需要整体参考时使用。

### `metadata.json`

Skill 元数据，例如来源和版本。

### `README.md`

面向开发者的说明。

## `.agents` 与根 `AGENTS.md` 的区别

这是最容易混淆的地方。

### 根 `AGENTS.md`

是当前仓库的强制开发规则，例如：

- 先读代码再修改。
- 不改无关文件。
- 前端目录约定。
- 画布 UI 规范。
- 文档和发版流程。

它对本项目中的所有 Agent 开发行为持续生效。

### `.agents/skills/*/SKILL.md`

是特定任务才加载的专业能力说明。

例如只有在做 React 优化时才需要 Vercel Skill。

可以理解为：

```text
根 AGENTS.md = 项目法律
.agents/skills = 专业参考手册
```

专业参考手册不能推翻项目法律。

## `.agents` 与运行时画布 Skill 的区别

项目中还有：

```text
plugins/infinite-canvas/skills/
```

区别如下：

| 目录 | 使用者 | 用途 |
| --- | --- | --- |
| `.agents/skills/` | 在仓库中开发代码的 Agent | 指导前端设计、React 性能等开发任务 |
| `plugins/infinite-canvas/skills/` | 安装 Infinite Canvas 插件的 Codex / ZCode | 指导打开和操作画布 |
| `canvas-agent/src/skills/` | Canvas Agent 服务 | 管理用户工作空间中的 Agent Skill |

它们处于不同层级，不应混为一谈。

## Skill 是如何被使用的

一般流程：

```text
用户提出任务
    ↓
Agent 判断任务是否匹配某个 Skill 描述
    ↓
读取对应 SKILL.md
    ↓
按 Skill 要求读取必要规则
    ↓
结合根 AGENTS.md 和现有代码执行任务
```

Skill 不会自动修改代码，它只改变 Agent 执行任务时遵循的工作流程和质量标准。

## 什么时候需要修改这个目录

常见场景：

- 增加新的项目级 Agent Skill。
- 升级 Vercel React 规范版本。
- 调整前端设计 Skill。
- 修改本地插件市场发现配置。
- 修复 Skill 触发描述不准确的问题。

普通产品功能开发通常不需要修改 `.agents/`。

## 新增 Skill 的基本结构

最小结构通常是：

```text
.agents/skills/my-skill/
└── SKILL.md
```

`SKILL.md` 一般包含：

```yaml
---
name: my-skill
description: 这个 Skill 在什么情况下使用
---
```

正文应明确：

- 何时使用。
- 何时不要使用。
- 执行步骤。
- 需要读取的参考文件。
- 输出要求。
- 安全限制。

如果包含脚本、模板或参考资料，可以继续增加：

```text
scripts/
references/
assets/
```

## 修改 Skill 时的原则

- 触发描述要具体，避免所有任务都误触发。
- 指令要可执行，不要只写抽象口号。
- 大型规则按主题拆文件。
- 引用相对路径时，以 Skill 自己的目录为基准。
- 保留第三方来源、版本和许可证。
- 不在 Skill 中存放 API Key、token 或私人信息。
- 不把当前一次任务的临时进度写成长期规则。

## 常见需求应该去哪里改

| 需求 | 位置 |
| --- | --- |
| 修改 Infinite Canvas 插件发现 | `.agents/plugins/marketplace.json` |
| 修改前端设计指导 | `.agents/skills/frontend-design/SKILL.md` |
| 修改 React Skill 触发条件 | `.agents/skills/vercel-react-best-practices/SKILL.md` |
| 修改某条 React 性能规则 | 对应 `rules/*.md` |
| 修改项目强制开发规则 | 根目录 `AGENTS.md`，不是这里 |
| 修改 Agent 操作画布说明 | `plugins/infinite-canvas/skills/`，不是这里 |

## 小白推荐阅读顺序

1. 根目录 `AGENTS.md`：先理解项目强制规则。
2. `.agents/plugins/marketplace.json`：理解插件发现。
3. `frontend-design/SKILL.md`：看一份较短的 Skill。
4. `vercel-react-best-practices/SKILL.md`：看规则索引。
5. 任选一个 `rules/*.md`：理解规则如何拆分。
6. 对照 `plugins/infinite-canvas/skills/`，理解不同 Skill 的使用对象。

## 容易踩坑的地方

- `.agents/` 不参与网页运行，不要把业务代码放进来。
- Skill 是指导文档，不是 React hook、npm 包或 MCP 工具。
- 不要用 Skill 规则覆盖根 `AGENTS.md` 的项目约束。
- 不要混淆三套 Skill：开发 Agent、Codex/ZCode 插件、Canvas Agent 工作空间。
- 第三方 Skill 的许可证和来源信息要保留。
- `marketplace.json` 的相对路径依赖当前目录结构，移动插件目录会导致发现失败。
- 修改触发描述可能影响很多后续任务，应保持边界清晰。
